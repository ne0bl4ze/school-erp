Problem Statement 03 / 14

Why does a school need an ERP?

Traditional schools manage attendance registers, grade sheets, fee receipts, and timetables manually — leading to errors, delays, and no real-time visibility for parents or students.

✗
Paper attendance registers — error-prone and hard to audit
✗
Fee tracking via spreadsheets — no payment history
✗
Report cards printed manually — time consuming
✗
Parents have no real-time updates on their child
✗
No centralised platform for notices and announcements

Our Solution

Centralised Web Platform

One login for students, teachers, and admins — each seeing only what their role permits.

Real-time Data

Attendance marked instantly, grades entered and visible immediately, fees tracked with full transaction history.

Automated Alerts

Parents get email alerts for low attendance, fee confirmation, and leave approvals — via Nodemailer.

JWT Auth Middleware
const protect = async (req, res, next) => {
  const token = req.headers
    .authorization?.split(' ')[1];
  const decoded = jwt.verify(
    token, process.env.JWT_SECRET
  );
  req.user = await User.findById(decoded.id);
  next();
};
RBAC Middleware
const allow = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role))
    return res.status(403).json({
      message: `Access denied`
    });
  next();
};

// Usage in routes:
router.post('/mark', protect,
  allow('teacher', 'admin'), ctrl);

Implementation 12 / 14

Challenges & Solutions

⚠ Challenge

Mongoose findOneAndUpdate bypasses the pre('save') hook — seed script stored plain-text passwords, breaking login.

→
✓ Solution

Changed seed to use new User({...}).save() which triggers the bcrypt hashing hook correctly.

⚠ Challenge

Mongoose populate() for course data was failing silently — timetable, attendance, and syllabus pages all returned empty data.

→
✓ Solution

The Course model was never require()'d anywhere. Added all model imports to index.js before routes load.

⚠ Challenge

Vite's dev proxy works for local development but is stripped in production builds — frontend API calls broke on deployment.

→
✓ Solution

Used import.meta.env.VITE_API_URL as the base URL — falls back to /api in dev, uses Railway URL in production.

⚠ Challenge

macOS AirPlay Receiver permanently occupies port 5000, causing the Express server to crash on startup.

→
✓ Solution

Switched backend to port 8000 via .env, updated Vite proxy target accordingly.
